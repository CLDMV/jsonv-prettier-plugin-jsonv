# @cldmv/prettier-plugin-jsonv v1.1.1 Changelog

**Release Date**: October 2026
**Release Type**: Patch

---

## Overview

A maintenance release with no change to the plugin's behavior. Every source, test, config and workflow file now carries the uniform CLDMV file header, maintained by `@cldmv/fix-headers` from the shared `@cldmv/configs` config, and the CI `✅ Required PR Check` mirror can no longer be satisfied by a skipped run. The only edits to `src/index.mjs` are to its header comment.

---

## 🔧 CI & tooling

### Uniform file headers from the shared CLDMV config ([#44](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/44))

A new `fix:headers` script runs `@cldmv/fix-headers` against `.configs/fix-headers.json`, which extends `@cldmv/configs/fix-headers.json` and excludes `tests/fixtures/` (the fixtures are byte-exact and must not gain a header). The first run stamped every file: files that had no header (the tests, the ESLint and vitest configs, the pre-commit installer) gained one, existing header dates were rewritten in ISO 8601 form (`2026-04-25T16:34:42-07:00`), and every header gained an empty comment line inside its opening and closing.

### A skipped PR run no longer satisfies Required PR Check ([#45](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/45))

On an in-repo feature PR, the `pull_request` run skips the `required-check` mirror job because the push run on the head branch owns the status. GitHub still posts a check run for a skipped job and treats a skipped required check as passing, so the skipped job, named `✅ Required PR Check`, could green-light the ruleset (and auto-merge) before the push run's real mirror existed. The job name is now an expression that evaluates to `✅ Required PR Check` only on the paths that own the status.
