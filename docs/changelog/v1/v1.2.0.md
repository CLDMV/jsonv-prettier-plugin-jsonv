# `@cldmv/prettier-plugin-jsonv` v1.2.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/1.2.0`

---

## Overview

The plugin now loads from CommonJS. `require("@cldmv/prettier-plugin-jsonv")` returns the plugin object, so it works from a `.prettierrc.cjs` or `prettier.config.cjs` as well as from an ES module config. The build moves to tsup, and a `prettier-plugin-jsonv-dev` export condition lets a checkout run against `src/` instead of the built `dist/`.

The plugin's formatting code is unchanged: `src/index.mjs` is byte-for-byte the same as in v1.1.4, so a given `.jsonv` file formats exactly as before.

The one requirement change is the Node.js floor. `engines.node` goes from `>=18.0.0` to `>=22.22.0`. See [Breaking Changes](#-breaking-changes) and the upgrade notes.

This release also carries the dev-dependency updates queued for v1.1.5, which was never published on its own.

## ✨ Features

### CommonJS entry and tsup build ([#84](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/84), fixes [#82](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/issues/82))

Until now the `"."` export was ESM-only, so a CommonJS Prettier config couldn't `require()` the plugin. The package now has a CommonJS entry:

- `src/index.cjs` sits next to `src/index.mjs`. It checks that the running Node.js can `require()` an ES module, then sets `module.exports = require("./index.mjs").default`, which is the plugin object (`languages`, `parsers`, `printers`, `options`) Prettier expects from a CommonJS plugin. On a Node.js without `require(esm)` it throws an `ERR_REQUIRE_ESM` error that names the required version and suggests `import()` instead.
- `"."` gets `require: ./dist/index.cjs` next to the existing `import: ./dist/index.mjs`, and `main` now points at `dist/index.cjs`.
- tsup replaces the custom `scripts/build.mjs`. It bundles `src/index.mjs` into `dist/index.mjs`, minified with names kept, and leaves the `@cldmv/jsonv` and `prettier` peers external. `dist/index.cjs` is not a second bundle: tsup copies `src/index.cjs` there verbatim, so the plugin code ships once. Sourcemaps are built for local debugging and left out of the tarball.
- `scripts/fix-types.mjs` is gone. The `types` entry points at the generated `types/src/index.d.mts` instead of a copy in `types/dist/`.
- `prepack` runs the build, so a packed or published tarball always contains a fresh `dist/`.

The README's config examples now use the real package name (they said `prettier-plugin-jsonv`), and it documents the CommonJS config. In a JSON `.prettierrc`, list the plugin by name: `"plugins": ["@cldmv/prettier-plugin-jsonv"]`.

### `prettier-plugin-jsonv-dev` export condition ([#84](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/84))

`"."` carries a `prettier-plugin-jsonv-dev` condition that maps `import` to `src/index.mjs` and `require` to `src/index.cjs`. Run Node with `--conditions=prettier-plugin-jsonv-dev` (or put it in `NODE_OPTIONS`) to load the source in a checkout. Without it, the package loads the built `dist/`, which needs `npm run build` first. Published installs only contain `dist/`, so the condition has no effect there.

The Vitest suite runs with the condition, so it tests `src/`. `npm test` then builds and runs `tests/cjs/entry.test.cjs` with `node --test` against `dist/`, including a format through a CommonJS Prettier config.

## 💥 Breaking Changes

### Node.js 22.22.0 or later is required ([#84](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/84))

`engines.node` rises from `>=18.0.0` to `>=22.22.0`, even though this is a minor release. The CommonJS entry needs a Node.js that can `require()` an ES module without a warning, and the build and test toolchain now needs a recent Node.js 22 (tsup 9 alone requires 22.18 or later), so older versions can no longer be tested. The floor is set at 22.22.0, and the CI and publish matrices start there.

On an older Node.js, npm prints an `EBADENGINE` warning on install, or refuses to install when `engine-strict` is set. Older versions are no longer tested or supported.

## 🔒 Security & supply chain

- `overrides` pin `katex` to `>=0.19.1 <1.0.0` and `minimatch` to `^11.0.3`, which clears advisories that reach the repository through `@eslint/markdown` and ESLint ([#85](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/85)). Both are development-only, and neither ships with the plugin.

## 🔧 CI & tooling

- `ci.yml` sets `coverage_build_command: "npm run build:ci"`, so the coverage jobs build the package the same way CI does ([#84](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/84)).
- `bundle-size.yml` measures the published `dist/` files (`dist/**.mjs`, `dist/**.cjs`) instead of `dist/**` plus `types/dist/**` ([#84](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/84)).
- `tmp/` is gitignored ([#83](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/83)).

## Upgrade notes

- **Node.js 22.22.0 or later is now required** (it was 18.0.0). This is a real requirement change: upgrade Node.js before upgrading the plugin.
- Formatting output is unchanged, and ES module configs need no changes.
- CommonJS configs can now `require("@cldmv/prettier-plugin-jsonv")` directly and pass the result in `plugins`.
- Contributors: run the tests with `npm test`, which applies the `prettier-plugin-jsonv-dev` condition. Run `npm run build` before loading the package from `dist/` in a checkout.
