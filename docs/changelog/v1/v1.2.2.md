# `@cldmv/prettier-plugin-jsonv` v1.2.2 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/1.2.2`

---

## Overview

v1.2.2 is a development-tooling release. The test config now resolves the plugin through the `prettier-plugin-jsonv-dev` export condition the way it was meant to, and the type scripts are split into `types:check` (type-check without emitting) and `types:build` (emit declarations).

No plugin code changed. A given `.jsonv` file formats exactly as it did in v1.2.1, and nothing changes for anyone installing the package.

---

## 🔧 CI & tooling

### Tests run against `src/` through `devCondition()` ([#91](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/91))

`.configs/vitest.config.mjs` set `test.nodeOptions` to pass `--conditions=prettier-plugin-jsonv-dev` to the test workers, but vitest has no such option, so the condition never reached them. The config now builds on `devCondition()` from `@cldmv/configs` (bumped to `^1.4.0`), which sets the resolver conditions and the worker `execArgv`, so Node's own resolver picks `src/` through the `prettier-plugin-jsonv-dev` export condition too.

### `types:check` added, `build:types` renamed to `types:build` ([#93](https://github.com/CLDMV/jsonv-prettier-plugin-jsonv/pull/93))

- New `types:check` runs `tsc -p .configs/tsconfig.types.jsonc --noEmit` (`checkJs` and `strict`, so a JSDoc type error fails it) and is what CI's type-check step runs, instead of `test:types`.
- `build:types` is now `types:build`, which emits the declarations. `test:types` and the comments in `tsconfig.types.jsonc`, `.prettierignore` and `ci.yml` use the new name.
- `test:types` keeps its job: it rebuilds the declarations and compiles the consumer test in `tests/types/` against them, as part of `build:ci`.
